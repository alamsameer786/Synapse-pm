Quick Start Guide

Get up and running with the SynapsePM API in minutes. Follow these steps to start predicting equipment failures with our AI platform.

code_blocks API version: v1.0

1. Create an Account

Sign up for a free account at synapsepm.com/signup. No credit card required for the 14-day trial.

2. Get Your API Key

After logging in, navigate to Dashboard → Profile Menu → API Keys and generate a new key. The key format is:

API Key Format 
spm_9fK2xQvLmN8pRtY4hW3jZ6aB1cD5eF7gH0iJ2kL4mN6oP8q

⚠️ Important: Never share your API keys or commit them to version control. Use environment variables or secure secret managers.

3. Make Your First API Call

Use your API key to authenticate requests. Here's an example using cURL:

cURL 
curl -X GET https://api.synapsepm.com/api/v1/machines \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
Python 
import requests

headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}

response = requests.get(
    "https://api.synapsepm.com/api/v1/machines",
    headers=headers
)
print(response.json())

Authentication

SynapsePM supports two authentication methods: JWT Bearer tokens (from the login endpoint) and API keys for server-to-server integrations. Include the credential in the Authorization header.

Login (JWT)

POST /api/v1/auth/login

Authenticate with email and password to obtain access + refresh tokens.

Login request 
curl -X POST https://api.synapsepm.com/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@company.com","password":"your-password"}'
Login response 
{
  "success": true,
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": "2a4c1f...",
    "email": "you@company.com",
    "display_name": "Your Name",
    "role": "org_admin"
  }
}

Authenticated headers

Headers 
Authorization: Bearer YOUR_ACCESS_TOKEN
Content-Type: application/json

Credential types

Type Format Use Case
Access Token JWT (from /auth/login) Browser / mobile clients
API Key spm_... Server-to-server integration
Device Key spm_dev_... IoT sensor ingestion (X-Device-Key)

Machines API

Manage your industrial equipment and monitor their health status.

GET /api/v1/machines

Returns a paginated list of all machines in your organization.

Query parameters

Parameter Type Description
pageintegerPage number (default: 1)
per_pageintegerResults per page (default: 20, max: 100)
statusstringFilter by status: online, offline
searchstringSearch by name or serial number
Example response

Create a machine

POST /api/v1/machines

Create a new machine in your organization.

Create request 
curl -X POST https://api.synapsepm.com/api/v1/machines \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Turbine A-42",
    "machine_type": "turbine",
    "location": "Floor 2",
    "manufacturer": "Siemens"
  }'

Predictions API

Get RUL (Remaining Useful Life) predictions and failure probabilities for your equipment using our trained ML models.

POST /api/v1/machines/{machine_id}/predict

Run a fresh prediction for a specific machine using its recent sensor data.

POST /api/v1/predictions/predict-dataset

Run a prediction on an uploaded dataset file (CSV / XLSX / JSON).

GET /api/v1/predictions/history

Get the prediction history for your organization, optionally filtered by machine.

Alerts API

Manage and respond to AI-generated alerts for your equipment.

GET /api/v1/alerts

Returns a paginated list of active and historical alerts for your organization.

POST /api/v1/alerts/{alert_id}/acknowledge

Acknowledge an alert so the team knows someone is handling it.

POST /api/v1/alerts/{alert_id}/resolve

Mark an alert as resolved with optional resolution notes.

POST /api/v1/alerts/mark-all-read

Mark all active alerts in the organization as read.

Webhooks

Receive real-time notifications when predictions are generated or alerts are triggered. SynapsePM emits events over WebSocket and can push to configured HTTP endpoints.

POST /api/v1/webhooks/configure

Configure a webhook endpoint URL to receive events.

Event types

Event Trigger
machine.createdA new machine is added
machine.updatedMachine details or status change
prediction.createdA new prediction is generated
alert.createdA new alert is triggered
alert.updatedAlert acknowledged or resolved

Error Handling

The API uses standard HTTP response codes to indicate success or failure.

Code Description
200Success
201Created
400Bad Request — invalid parameters
401Unauthorized — invalid or missing credentials
403Forbidden — insufficient permissions
404Not Found — resource does not exist
422Unprocessable — prediction abstained (no compatible model)
429Too Many Requests — rate limit exceeded
503Service Unavailable — model or dependency not ready

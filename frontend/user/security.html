Security Infrastructure

How We Protect Your Data

Real measures, running in the code today — not marketing claims

password

Password Hashing

Every password is hashed with Argon2id — the winner of the Password Hashing Competition. Plain-text passwords are never stored. Legacy hashes are automatically re-hashed on the next login.

encrypted

Field Encryption

Sensitive stored values are encrypted with Fernet (AES-128-CBC + HMAC-SHA256). Your integration keys, secrets, and internal credentials never sit in plain text.

vpn_key

Session Management

JWT access tokens with short expiry, revocable refresh tokens, and a server-side session store. You can view and revoke any session — including WebSocket connections — at any time.

admin_panel_settings

Access Control & MFA

Role-based permissions (viewer, operator, admin, super-admin) enforced on every endpoint. Optional TOTP multi-factor authentication with backup codes, compatible with Google Authenticator, Authy, and 1Password.

shield_lock

Tenant Isolation

Every query is scoped to your organization ID. Cross-tenant access returns 404 — never 403 — so we never confirm that another tenant's resource exists.

receipt_long

Audit Logging

Every sensitive action is recorded in a tamper-evident, hash-chained audit log. Each entry references the previous entry's hash — any retroactive change would break the chain.

Common Questions

Security FAQ

Straight answers about how the platform is built

Your data lives on the infrastructure you deploy SynapsePM to. That can be a cloud database you control, or a self-hosted PostgreSQL instance inside your own network. We never silently move your industrial data between jurisdictions.
All traffic between your browser or devices and SynapsePM is sent over TLS. For production deployments, we recommend terminating TLS at a reverse proxy (Nginx, Caddy, or your cloud load balancer) with HSTS enabled.
Google, GitHub, and LinkedIn OAuth are supported out of the box. Enterprise customers can request SAML 2.0 or OIDC integration with their own identity provider (Okta, Azure AD, Auth0) as part of a custom deployment.
Each machine gets its own device key, generated once and shown only once — we store a SHA-256 hash, never the raw key. Devices send readings with an X-Device-Key header, and every key tracks its own usage count and can be revoked instantly from the dashboard.
Account deletion is soft-first: your profile is anonymized immediately (name, phone, avatar removed), all sessions and API keys are revoked, and the account is queued for hard deletion after 30 days. You can contact us to reverse the deletion within that window.
Failed logins are counted per user. After a configurable number of attempts (default 5), the account is locked for a short period (default 15 minutes). All login attempts — successful or not — are recorded in the login history with IP and user agent.
